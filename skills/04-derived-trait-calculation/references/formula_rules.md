# 公式型计算规则

## 计算流程

```
查 derived-traits 注册表
  ↓
检查 required_traits 是否齐备        → 缺则 E041 中止
  ↓
公式字符白名单校验                   → 违规则 E043 中止
  ↓
逐行求值
  ↓
guards 不满足 → 结果置 NaN，记 change_log
  ↓
validation 越界 → 结果置缺失，记 change_log
  ↓
计算前后统计
```

## 公式安全约束

公式通过受限求值执行，**字符白名单**仅允许：

```
字母 数字 下划线 空格
+ - * / ( ) .
```

出现 `import`、`__`、`;`、`lambda`、反引号、方括号等一律拒绝（`E043`）。这是防止配置文件被篡改后变成代码注入入口。

## guards 与 validation 的区别

| | 含义 | 不满足时 |
|---|------|---------|
| `guards` | 计算的**前置条件**（如 `WG > 0` 防除零） | 该记录不计算，结果置 NaN |
| `validation` | 结果的**合理性检验**（如 `FCR <= 10`） | 结果置缺失并记录原值 |

两者都要写入 change log，且在统计中分别计数——"没算出来"和"算出来但不合理"是两回事，不能混在一起报。
