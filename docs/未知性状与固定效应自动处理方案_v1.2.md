# 未知性状与固定效应自动处理方案（v1.2，已落地）

> 背景：先生要求"衍生性状计算里要能处理未知性状加进来的情况——自动用英文母代替、并做好；固定效应等若出现未知项也要有处理策略"。
> 先生定调（17:57 后）：① 代号用英文**缩写**，如产蛋→CD；② 凡**中文表头**的固定效应，要**全部转换为英文**。
> 现状缺口：原 `run_phenotype_qc` 只处理"任务显式请求的"性状/固定效应；数据里多出来、既未被请求也未被 `trait-registry.yaml` 注册的列（尤其是中文表头），会被整列忽略（不报错、不记录、不进模型）。这正是缺口。
> 设计原则（不可破）：① 不静默——任何中文/未知表头必须被发现、被转换、被记录；② 可追溯——原始中文名 → 英文代号映射必须落盘；③ 不发明——绝不为未知列编造衍生公式，只做"转英文名 + 分类 + 可选纳入"。

**实施状态：已于 2026-10-13 落地并通过单测（见第七节）。**

## 一、中文表头 → 英文代号 转换层

新增模块 `tools/Python/abges_unknown.py`，函数：

- `resolve_code(header, alias_map, cn_map, dict_map, used_codes, cfg)` → 返回 `(code, source)`，`source ∈ {alias_registry, registry, dictionary, pinyin, fallback}`。
- `classify_column(series, cfg)` → 返回 `(role, reason)`，`role ∈ {fixed, trait_or_covariate, excluded}`。
- `normalize_headers(frame, cfg, registry=None, dict_map=None)` → 返回 `(new_frame, rename_map, report)`，`report` 每列含 `{original, code, source, role, reason, action}`。
- `write_unknown_map(report, out_dir, run_id=None)` → 落盘 YAML。

**代号生成四级优先级（先生定调：用英文缩写，如产蛋→CD）**：

| 优先级 | 来源 | 示例 | 说明 |
|--------|------|------|------|
| P1 | `configs/column-aliases.yaml` 统一别名注册表（2026-10-16 新增） | 翅号→`ID`、批次→`Batch`、`pjlc`→`ACL` | 全系统列名标准化的单一权威数据源，替换分散的 header_map + header_translation + name_cn |
| P2 | `trait-registry.yaml` 的 `name_cn` 命中 | 产蛋数→`EN`、体重→`BW`、家系→`Family` | 已知点用规范码，保证与既有分析口径一致 |
| P3 | `configs/traits/header_translation.yaml` 人工词典（降级兼容） | 笼位→`Cage`、栋舍→`House` | 覆盖注册表外的常用中文表头；column-aliases.yaml 优先 |
| P4 | **pypinyin 拼音首字母兜底** | 养殖方式→`YZFS`、产蛋→`CD` | 先生明确示例"产蛋→CD"即此路；依赖轻量纯 Python 库 `pypinyin`（已装 D 盘 venv） |

- 三级均失败（非中文、非已知）→ 退化为 "`UX_` + base26 字母"保底（`UX_A` / `UX_B` / …），确保必有代号。
- **碰撞规避要点**：`used_codes` 仅以「现有列名」为初值，**不得并入已知 trait_id 集合**——否则注册表 `name_cn→trait_id` 的映射会被自身占用的 trait_id 挡掉（如 体重→BW 因 BW 已是已知代号而被拒，退化成拼音），这是实现中踩过的坑，已修正。
- 落实"英文母代替"：`working.rename(columns=rename_map)`，下游（HIBLUP 命令、ANOVA、衍生计算）统一用英文代号引用，原始中文名仅存于映射表。

## 二、分类启发式（trait vs 固定效应 vs 排除）

对**原本未知**的列（现已有英文代号）按内容判定角色（关键修正见下）：

| 指标 | 计算 | 判据 |
|------|------|------|
| `id_ratio` | `n_unique / n_rows` | ≥ `id_uniqueness_ratio`(默认0.9) → 疑似个体号/重复标记 → **排除** |
| `n_unique` | 非空去重数 | ≤ `fixed_max_levels`(默认30) → **固定效应**（无论是否数值） |
| `numeric_ratio` | 可转数值的非空占比 | 高基数且 ≥ `numeric_ratio_min`(默认0.5) → **trait/协变量**；高基数且非数值 → **排除** |

> **修正（2026-10-13 实测）：** 原草案把 `numeric_ratio < 0.5` 直接判为排除，会**错误丢弃所有分类固定效应**（Gen/Batch/Sex/Family 均为非数值字符串）。固定效应多为低基数分类列，故改为「先判 id_ratio 排除疑似 ID → 再按 n_unique ≤ 阈值判固定效应（不论数值）→ 高基数再按数值占比判连续型」。该修正已写入 `classify_column` 并经单测覆盖。

## 三、治理策略（默认行为 + 开关）

配置段位于 `configs/qc/phenotype-qc.yaml` 的 `unknown_columns:`（随配置 v1.4 引入）。

| 未知类型 | 默认行为 | 控制开关 | 说明 |
|----------|----------|----------|------|
| **中文表头固定效应** | **必须全部转英文代号**；转后按内容判为固定效应并**默认纳入建模** | `enabled`（总开关，默认 true）；`auto_include_unknown_fixed_effects`（默认 **true**） | 先生明确要求中文固定效应全转英文，故默认纳入 |
| 未知连续列（已转英文） | 仅登记为候选并**告警，默认不自动入模** | `auto_register_unknown_traits`（默认 **false**） | 防模型污染：避免静默注入未知性状/协变量，须人工复核或显式打开 |
| 疑似 ID / 文本 | 排除 | 不可纳入 | `id_ratio` 过高或高基数非数值 |

- **纳入范围约束**：自动纳入**仅针对「中文来源」列**（`source ∈ {registry, dictionary, pinyin, fallback}`）。英文表头（不论是否已知）一律**不自动纳入**，交由显式请求逻辑处理——避免对未知英文列静默改选。
- **绝不自动编造衍生公式**：未知列一律按 raw 处理；衍生公式仍须来自 `derived-traits.yaml`。
- 所有中文/未知表头清单 + 映射表在 QC 报告 `unknown_columns` 段**显著列出**，并落盘运行目录。任何纳入/跳过均写 `change_log` + 告警，原始中文名全程可追溯。

## 四、与各子系统的集成点（已实现）

1. **`abges_phenotype.py::run_phenotype_qc`**（主集成点）
   - **阶段一（更名，PH001 之前）**：`normalize_headers` 转换列名，`rename_detail.update(auto_rename)` 复用既有「原名→标准名」语义，保留 `_align_declared` 对齐能力；`result.unknown_columns = report`。
   - **阶段二（纳入，PH005 之后）**：`_auto_include_unknown_columns(...)` 把中文来源的固定效应纳入 `effective_fixed_effects`、连续列按开关处理；**必须在 PH005 之后**——PH005 会整体重赋值 `effective_*`，若提前纳入会被覆盖（实现中踩过此坑，已修正）。
   - 仅当存在被转换/发现的未知列时才落盘 `unknown_columns_map_<run_id>.yaml` 到 `unknown_columns.map_output`（默认 `workspace/intermediate`，运行时瞬态、.gitignored）。
   - `PhenotypeQCResult` 新增字段：`unknown_columns` / `auto_included_fixed_effects` / `auto_included_covariates`，并在 `to_dict` 输出。
2. **`MultiTraitQCResult`**：逐性状结果聚合 `unknown_columns`（按 original 去重）与 `auto_included_*` 列表，`to_dict` 同步输出。
3. **`breed_insights.py`（ANOVA）/ `hiblup_tool.py`**：本就遍历 `effective_fixed_effects` / `effective_covariates`，列已转英文代号，命令装配（`--dcovar/--qcovar`）自然衔接，无需改逻辑。
4. **`trait-registry.yaml`**：其 `name_cn` 直接作为优先级 1 字典源；新增 `configs/traits/header_translation.yaml` 承载优先级 2 人工词典。

## 五、实测落地的两处关键修正（务必知悉）

| # | 坑 | 现象 | 修正 |
|---|----|------|------|
| 1 | `known_codes` 自匹配 | `known_codes` 含 `frame.columns` 导致每列恒为「已知」→ 永不转换 | `known_codes` 仅用于英文列「是否已知标准代号」判定；`used_codes` 仅以 `frame.columns` 为初值 |
| 2 | 分类误删固定效应 | `numeric_ratio<0.5` 把 Gen/Batch/Sex/Family 等非数值分类列整列排除 | 改为先 id_ratio 排除 ID → n_unique≤阈值判固定效应（不论数值）→ 高基数再按数值占比判连续型 |
| 3 | PH005 覆盖自动纳入 | 提前纳入的中文固定效应被 PH005 重赋值 `effective_fixed_effects` 抹掉 | 自动纳入移至 PH005 之后执行 |
