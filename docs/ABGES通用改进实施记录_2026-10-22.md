## 已落地内容

1. **运行材料与检查点**：对外交付仍只发布 `reports/`、`output/` 白名单文件，运行 JSON 不进入最终交付目录。运行内部保留 `state.json`、元数据、QC 报告和日志。黑板检查点改成单份原子替换的 `checkpoint_blackboard.json`，避免每个阶段复制全量黑板而不断堆积；成功交付后清除该检查点及阶段矩阵并清空恢复指针；失败、中断或待决策运行保留恢复材料。
2. **三模型校验一致**：PBLUP/SSGBLUP 的预期个体来自 QC 后系谱，GBLUP 来自 QC 后基因型；G5-07 逐 ID 比对，检查缺失、额外、空白和重复 ID，不再只凭记录数通过。ID 集合不一致设为硬阻断。多性状 G5 的逐性状执行与最严结论合并已抽到 `runners/common.py`，三模型共用同一实现。
3. **阈值集中管理**：新增 `configs/validation/analysis-policy.yaml`，汇集表型记录数/剔除率、基因型样本与位点数、表型对接阈值、遗传力合法范围和 `SE/h²` 预警阈值。三套 runner 与整合模块读取同一配置；运行元数据写入完整策略快照。遗传力经验区间按物种组织，当前仅配置鸡性状，并只作为提示。
4. **任务契约运行时生效**：`abges_runtime/tasks.py` 运行时读取 `schemas/task-schema.yaml`，检查必填字段、未知字段、基本类型和输入角色；此外保留文件存在、模型名、性状个数等语义检查。
5. **文档同步**：更新 Agent 拓扑、工作流、Harness、架构、QC 规则、验证 Skill、模型配置、PLINK QC 配置和 Agent 03/05/08 说明，记录实际阶段顺序、并行分支、结果 ID 核验和检查点清理时机。
